# Модуль 04. Домашнее задание (СРС): Каталог книг (Book Catalog API)
## Архитектурные решения, шаблон Repository, DTO, AutoMapper и ReturnResult

---

### Архитектурный разбор компонентов системы

#### 1. Общая архитектурная цепочка вызовов
В проекте реализована классическая многослойная архитектура веб-сервиса:
```text
Клиент / Swagger
      │ (HTTP-запрос)
      ▼
BooksController
      │
      ├──► AutoMapper (преобразование BookDto ◄──► Book)
      │
      └──► IBookRepository (BookRepository)
                  │
                  ▼
            AppDbContext (EF Core ORM)
                  │
                  ▼
            SQLite Database (books.db)
```

#### 2. Назначение каждого элемента архитектуры
* **Entity (`Book`):** Модель предметной области, представляющая структуру таблицы `Books` в базе данных. Содержит все физические поля записи (`Id`, `Title`, `Author`, `Year`, `Price`, `Description`).
* **DTO (`BookDto`):** Объект передачи данных (Data Transfer Object). Служит внешним контрактом API. Изолирует клиент от изменений внутренней структуры базы данных и защищает от Overposting-атак.
* **DbContext (`AppDbContext`):** Главный связующий компонент Entity Framework Core. Управляет подключением к SQLite, выполняет SQL-запросы, маппит результаты на C#-объекты и обеспечивает атомарное сохранение изменений (`SaveChangesAsync`).
* **Repository (`IBookRepository` / `BookRepository`):** Паттерн, инкапсулирующий логику доступа к данным. Позволяет контроллеру оперировать коллекцией книг с помощью методов `GetAllAsync`, `GetByIdAsync`, `CreateAsync`, `UpdateAsync`, `DeleteAsync`, `GetByAuthorAsync`, не зная деталей реализации ORM.
* **AutoMapper (`AutoMapperProfile`):** Библиотека объектно-объектного маппинга. Выполняет автоматическое сопоставление свойств между `Book` и `BookDto`, избавляя код от ручного копирования каждого поля.
* **`ReturnResult<T>`:** Единая обертка ответов API. Обеспечивает предсказуемость формата ответа для клиентов (фронтенд, мобильные приложения):
  ```json
  {
    "isSuccess": true,
    "result": { ... },
    "errorMessage": []
  }
  ```

#### 3. Сценарий демонстрации работы в Swagger
1. **Создание книги (`POST /api/books`):**
   Отправка JSON с данными новой книги:
   ```json
   {
     "title": "CLR via C#",
     "author": "Джеффри Рихтер",
     "year": 2013,
     "price": 24000,
     "description": "Глубокое погружение в устройство среды CLR и .NET"
   }
   ```
   Ответ: `201 Created` с присвоенным `id: 4`.
2. **Получение книги (`GET /api/books` и `GET /api/books/4`):**
   Проверка наличия созданной книги в общем списке и по конкретному идентификатору.
3. **Изменение книги (`PUT /api/books/4`):**
   Изменение цены на `26000` и года издания. Проверка обновления записи.
4. **Поиск по автору (`GET /api/books/author/Мартин`):**
   Возвращает список книг Роберта Мартина («Чистый код», «Идеальный программист»).
5. **Удаление книги (`DELETE /api/books/4`):**
   Удаление записи и повторная проверка `GET /api/books/4` (возврат `404 Not Found`).

### Ответы на контрольные вопросы

#### 1. Что такое Entity в EF Core?
**Entity (сущность)** — это класс C#, сопоставленный с таблицей в базе данных, экземпляры которого соответствуют отдельным строкам этой таблицы.

#### 2. Зачем разделять Entity и DTO?
Для разделения ответственности и безопасности. Entity отражает структуру реляционной БД и может содержать служебные данные или циклические ссылки. DTO представляет контракт для клиента, позволяя отдавать только нужные данные и валидировать входящие запросы.

#### 3. Какую роль играет `AutoMapper`?
AutoMapper устраняет необходимость вручную переписывать свойства из одной модели в другую (устраняет рутинный код `Left-to-Right assignment`), обеспечивая чистый, лаконичный и поддерживаемый код.

#### 4. В чем преимущество паттерна `Repository` над прямым вызовом `DbContext`?
Репозиторий изолирует слой бизнес-логики от конкретной реализации ORM. Это позволяет легко подменять реальную БД на Mock-коллекцию в юнит-тестах, а также централизованно оптимизировать запросы к данным в одном месте.

#### 5. Почему единый формат ответа `ReturnResult` делает API надежнее?
Клиентский интерфейс всегда получает стабильную структуру с флагом `isSuccess`, данными `result` и списком ошибок `errorMessage`, что устраняет необходимость писать разные парсеры для успешных ответов и непредвиденных сбоев.
